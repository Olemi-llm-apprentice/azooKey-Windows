# v0.2.0 改善項目 設計仕様書

## 1. 概要

### 1.1 要望

v0.2.0では以下の改善を実施し、ユーザー体験と開発者体験の向上を図る：

1. **候補ウィンドウ位置計算とDPIスケーリング対応の改善**
   - 高DPI環境での表示位置ずれを解消
   - マルチモニター環境での正確な位置計算

2. **エラーログの改善**
   - リリースビルドでのログ出力対応
   - ログファイルの適切な管理（自動クリーンアップ）

3. **インストーラの改善**
   - アンインストール時のユーザーデータクリーンアップオプション

## 2. 要件定義

### 2.1 機能要件

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| REQ-001 | 高DPI環境（125%、150%、200%等）で候補ウィンドウが正しい位置に表示されること | 必須 |
| REQ-002 | マルチモニター環境で、入力中のモニターに候補ウィンドウが表示されること | 必須 |
| REQ-003 | 候補ウィンドウがモニター境界からはみ出さないこと | 必須 |
| REQ-004 | リリースビルドでもログファイルが出力されること | 必須 |
| REQ-005 | ログファイルが `%APPDATA%/Azookey/logs/` に保存されること | 必須 |
| REQ-006 | 古いログファイルが自動的に削除されること（最大10ファイル） | 推奨 |
| REQ-007 | アンインストール時にユーザーデータを削除するオプションがあること | 必須 |

### 2.2 非機能要件

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| NFR-001 | DPI取得処理がパフォーマンスに影響を与えないこと（1ms以下） | 必須 |
| NFR-002 | ログ出力がIME入力のパフォーマンスに影響を与えないこと | 必須 |
| NFR-003 | Windows 10/11の両方で動作すること | 必須 |

## 3. 設計詳細

### 3.1 DPIスケーリング対応 (`crates/ui/src/utils.rs`)

#### 3.1.1 DPIスケールファクター取得

```rust
fn get_dpi_scale_factor(monitor: HMONITOR) -> f64 {
    let mut dpi_x: u32 = 96;
    let mut dpi_y: u32 = 96;
    
    unsafe {
        let _ = GetDpiForMonitor(monitor, MDT_EFFECTIVE_DPI, &mut dpi_x, &mut dpi_y);
    }
    
    dpi_x as f64 / 96.0
}
```

**選択理由**: `GetDpiForMonitor` はモニターごとのDPIを正確に取得でき、マルチモニター環境でも正しく動作する。

#### 3.1.2 位置計算ロジック

```
┌────────────────────────────────────────────────────┐
│ キャレット位置 (物理座標)                           │
│     ┌───┐                                         │
│     │ A │← キャレット                             │
│     └───┘                                         │
│         ↓ (bottom + offset_y)                     │
│     ┌─────────────────┐                           │
│     │  候補ウィンドウ  │                           │
│     │                 │                           │
│     └─────────────────┘                           │
└────────────────────────────────────────────────────┘

下端がモニター外の場合:
┌────────────────────────────────────────────────────┐
│     ┌─────────────────┐                           │
│     │  候補ウィンドウ  │← 上に表示                 │
│     │                 │                           │
│     └─────────────────┘                           │
│         ↑ (top - height - offset_y)              │
│     ┌───┐                                         │
│     │ A │                                         │
│     └───┘                                         │
├────────────────────────────────────────────────────┤
│ モニター作業領域の下端                              │
└────────────────────────────────────────────────────┘
```

### 3.2 なぜその設計か

| 選択肢 | メリット | デメリット | 判断 |
|--------|---------|-----------|------|
| GetDpiForMonitor API | モニター別DPI取得可能、Windows 8.1以降対応 | 古いOSでは非対応 | ✅ 採用 |
| GetDpiForWindow API | ウィンドウ単位で正確 | ウィンドウ作成後のみ使用可能 | ❌ 不採用 |
| GetDeviceCaps | レガシー互換 | システム全体のDPIのみ | ❌ 不採用 |

**選択理由**: マルチモニター環境で各モニターのDPIが異なる場合に対応するため、`GetDpiForMonitor` を採用。Windows 8.1以降が対象のため、互換性の問題はない。

### 3.3 ログ機能改善 (`crates/client/src/trace.rs`)

#### 3.3.1 ログディレクトリ構成

```
%APPDATA%/
└── Azookey/
    ├── logs/                      # ログディレクトリ
    │   ├── 2025-11-26-02.30.00.json
    │   ├── 2025-11-26-02.35.00.json
    │   └── ...                    # 最大10ファイル
    ├── memory/                    # 学習データ
    ├── user_dictionary/           # ユーザー辞書
    └── settings.json              # 設定ファイル
```

#### 3.3.2 ログクリーンアップロジック

```rust
    // 2. 変更日時でソート（新しい順）
    // 3. MAX_LOG_FILES (10) を超えたファイルを削除
}
```

### 3.4 インストーラ改善 (`installer/Installer.iss`)

#### 3.4.1 削除対象ユーザーデータ

| パス | 内容 | 削除時の影響 |
|------|------|-------------|
| `%APPDATA%/Azookey/memory/` | 学習データ | 変換学習がリセット |

## 4. テスト仕様

### 4.1 DPIスケーリング テストケース

| テストID | シナリオ | 前提条件 | 手順 | 期待結果 |
|----------|---------|---------|------|---------|
| DPI-N-01 | 100% DPIでの位置計算 | DPI=96 | `get_dpi_scale_factor()` を呼び出し | スケールファクター 1.0 を返す |
| DPI-N-02 | 150% DPIでの位置計算 | DPI=144 | `get_dpi_scale_factor()` を呼び出し | スケールファクター 1.5 を返す |

## 5. 制限事項

| 制限 | 理由 | 回避策 |
|------|------|--------|
| Windows 8.1より前のOSは非対応 | GetDpiForMonitor APIが利用不可 | 古いOSではデフォルトDPI(96)を使用 |
| インストーラのUI言語は日本語のみ | 現在の対象ユーザーが日本語話者 | 将来的に国際化対応 |
| ログファイルの最大サイズ制限なし | 通常使用では問題にならない | 将来的にログローテーション追加を検討 |
